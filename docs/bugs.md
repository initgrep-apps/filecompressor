## Implementation Drift — 2026-09-29-slice-4b-self-contained-sidecars
**Date:** 2026-09-29 | **Plan:** docs/superpowers/plans/2026-09-29-slice-4b-self-contained-sidecars.md

1. Task 1 Step 2: Plan's bundle script defined `rewrite()` but applied it only to the sidecar — collected dylibs kept absolute `/opt/homebrew` load commands and failed the new audit (AC #2 requires dylibs load only `@rpath/*` + system). Plan fixed to rewrite every framework dylib too.
2. Task 1 Step 2: Plan's script was never idempotent (Global Constraint requires it): upfront `rm -rf frameworks/` + re-collect — a rewritten sidecar's deps are all `@rpath/*`, which `system_path` treats as done, so nothing is re-collected and the `-id` glob crashes under `set -e`; committed frameworks would be silently wiped. Plan fixed with an already-bundled guard (sidecar self-contained + frameworks populated → exit 0 untouched; rewritten sidecar + empty frameworks → hard FAIL).
3. Task 1 Step 2: Dyld resolves each image's `@rpath/*` loads via that image's OWN LC_RPATH — plan added rpaths only to the sidecar, so rewritten dylibs (brew libs carrying none of ours) would dylb-abort on end-user machines while the audit stayed green (audit reads `otool -L` only). Also, brew dylibs already reference some deps as `@rpath/*` (e.g. libOpenEXR → libIlmThread), which `collect` skipped as done → dangling refs. Plan fixed: rpaths added to every dylib, `collect` resolves `@rpath/*` deps via the referencing image's LC_RPATH entries (fails loudly when unresolvable), audit now fails dangling `@rpath/*` loads.
4. Task 1 Step 3: Plan's `bundle.macOS.frameworks: ["frameworks/*.dylib"]` glob is invalid — tauri-build 2.7 and tauri-bundler both treat entries as literal paths (`Path::exists` → "Library not found"), so the glob broke every `cargo build`. Config now carries the literal 65-entry list (generated from `src-tauri/frameworks/`); audit verifies the config list stays in sync with the frameworks dir.
